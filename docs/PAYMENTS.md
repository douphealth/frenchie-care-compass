# Production payment deployment

The repository now treats Stripe as the authority for premium access. Merging the code alone is not enough: the Edge Functions and Stripe webhook must be deployed to the Supabase project used by the production app.

## Required Supabase project secrets

Configure these as Edge Function secrets, never as Vite/browser variables:

- `STRIPE_SECRET_KEY` — Stripe secret key for the same mode as the configured Price.
- `STRIPE_PREMIUM_PRICE_ID` — active one-time Price for the Frenchie Care Vault.
- `STRIPE_WEBHOOK_SECRET` — signing secret generated by the Stripe webhook endpoint.
- `APP_ORIGIN` — `https://care-plan.frenchyfab.com`
- `RESEND_API_KEY` — required for purchase recovery email.
- `PREMIUM_FROM_EMAIL` — optional; defaults to `FrenchyFab <hello@frenchyfab.com>`.

## Edge Functions to deploy

- `create-payment`
- `get-pricing`
- `verify-payment`
- `stripe-webhook`
- `generate-plan` (contains the revised safety/credibility prompt)

The webhook function is intentionally configured with `verify_jwt = false` because Stripe cannot send a Supabase JWT. The function itself verifies Stripe's `stripe-signature` using `STRIPE_WEBHOOK_SECRET`.

## Stripe webhook

Create one endpoint for:

`https://zyxsijqazzhuudhmfitw.supabase.co/functions/v1/stripe-webhook`

Subscribe to:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`

Copy the endpoint signing secret into `STRIPE_WEBHOOK_SECRET`.

## End-to-end release check

Use Stripe test mode first.

1. Finish the free quiz and confirm the dashboard loads.
2. Download **Free Summary PDF** and verify it does not contain the premium feeding chart, printable grooming checklist, seasonal calendar, vet-prep sheets, or emergency reference.
3. Open the Vault. Verify the displayed price comes from Stripe.
4. Cancel Checkout. Confirm no premium access is granted.
5. Complete Checkout with a Stripe test card.
6. Confirm redirect includes `session_id` and shows **Payment verified** only after `verify-payment` succeeds.
7. Download the premium PDF and confirm premium-only pages are present.
8. Confirm the Stripe webhook succeeds and the buyer receives a recovery email.
9. Reload the success/recovery URL and confirm the purchase can be re-verified from Stripe.
10. Refund the payment, revisit the recovery URL, and confirm premium verification is denied.

Repeat the successful-purchase path with live-mode keys and a real low-value transaction before calling production payments verified.

## Rollback

If production checkout regresses, roll back the application deployment to the previous main commit and redeploy the previous Edge Function versions. Do not delete Stripe customers, payments, or webhook history during rollback.
